# 태스크 위젯 설계 (투두 · 캘린더 · 뽀모도로)

작성일: 2026-10-31

## 1. 무엇을, 왜

윈도우 화면 오른쪽에 떠 있는 가로 약 500px의 세로 패널 위젯. 작업하면서 할 일과 일정을 한눈에 보고, 뽀모도로 타이머로 집중 시간을 관리한다. 데이터는 서버에 저장해 어느 PC에서 로그인해도 같은 내용이 보인다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 화면 오른쪽에 떠 있는 패널 하나에 타이머 · 투두 · 미니 캘린더가 클릭 없이 다 보인다.
- 설정에서 세 섹션을 각각 켜고 끌 수 있다.
- 이메일, 구글, 카카오로 로그인하고 같은 이메일은 한 계정으로 취급된다.
- 투두와 일정은 서버에 저장된다.

**비목표 (v1에 안 넣음)**
- 실시간 동기화(두 PC 동시 반영). 창에 포커스가 오거나 주기적으로 다시 불러오는 정도로 충분.
- 뽀모도로 기록 저장, 통계.
- 반복 일정, 일정 알림, 외부 캘린더(구글 캘린더) 연동.
- 투두 마감일, 우선순위, 태그, 드래그 정렬.
- 모바일 · 웹 클라이언트.
- 화면 공간 차지(AppBar). 위젯은 다른 창 위에 떠 있기만 한다.
- macOS 지원 (윈도우 전용으로 만든다. 막지는 않음).

**반목표 (이러면 실패)**
- 위젯이 다른 작업을 가린다고 느껴질 만큼 크거나 거슬린다.
- 로그인이 자주 풀린다.
- 같은 이메일인데 구글/카카오/이메일 계정이 따로 생겨 데이터가 갈린다.

## 3. 구성

```
[Tauri 위젯 (Windows)]  --HTTPS-->  [PocketBase (Dokploy)]
 React + Vite + Tailwind                인증(이메일/구글/카카오)
 pocketbase JS SDK                      todos, events 컬렉션
 React Query                            관리자 UI
```

- **백엔드**: PocketBase 컨테이너 하나를 Dokploy에 따로 배포. 백엔드 코드는 짜지 않는다. DB, API, 인증, 관리자 UI가 모두 PocketBase 기본 기능.
- **클라이언트**: Tauri 2 + React. 위젯이 pocketbase JS SDK로 서버에 직접 붙는다. Rust 쪽은 창 제어(트레이, 항상 위, 위치, 자동 실행)만 맡는다.
- 글로벌 규칙의 BFF 패턴(Next.js API Route 경유)은 이 프로젝트에 해당 없음. 인가는 PocketBase 컬렉션 규칙이 서버에서 한다.

## 4. 백엔드 (PocketBase)

### 배포
- Docker 이미지로 Dokploy에 배포, 도메인 + HTTPS 연결.
- `pb_data` 폴더는 볼륨으로 유지 (데이터 유실 방지).
- 스키마는 `pb_migrations/`의 JS 마이그레이션 파일로 저장소에 남긴다 (관리자 UI에서만 만들면 재현이 안 됨).

### 컬렉션

**users** (PocketBase 기본 auth 컬렉션)
- 이메일/비밀번호 로그인 켬. 이메일 인증 필수.
- OAuth2: 구글, 카카오 켬.
- 앱 안에서 이메일 회원가입 가능 (가입 → 인증 메일 → 인증 후 로그인).

**todos**
| 필드 | 타입 | 비고 |
|---|---|---|
| user | relation(users) | 필수 |
| title | text | 필수 |
| done | bool | |
| created / updated | autodate | 정렬용 |

**events**
| 필드 | 타입 | 비고 |
|---|---|---|
| user | relation(users) | 필수 |
| title | text | 필수 |
| date | text | 필수. "YYYY-MM-DD" (설계자 판단: PocketBase date는 UTC 시각이라 한국 시간에서 날짜가 하루 밀릴 수 있어 문자열로 저장) |
| time | text | 선택. "HH:mm", 없으면 종일 |
| memo | text | 선택 |

**접근 규칙** (todos, events 모두, 목록/조회/생성/수정/삭제 전부)
```
@request.auth.id != "" && user = @request.auth.id
```
생성 시에도 `@request.body.user = @request.auth.id`로 남의 user를 못 넣게 한다.

### 계정 통합 (같은 이메일 = 한 계정)
- PocketBase는 OAuth2 로그인 시 같은 이메일의 기존 계정이 있으면 새로 만들지 않고 연결한다. 이 기본 동작을 그대로 쓴다.
- 조건: 기존 계정 이메일이 인증된 상태여야 한다. 그래서 이메일 가입은 인증 메일을 반드시 거친다.
- **SMTP 설정 필수** (인증 메일, 비밀번호 재설정). 서비스는 빌더가 고른다 (Resend, Gmail 앱 비밀번호 등).
- 카카오는 콘솔에서 이메일 동의항목을 켜야 이메일이 넘어온다. 이메일이 안 넘어오면 통합이 안 되므로 배포 시 확인 필요.
- (설계자 판단) OAuth 로그인 결과에 이메일이 없으면 계정을 만들지 않고 "이메일 제공에 동의해 주세요" 안내와 함께 로그인을 막는다. 이메일 없는 계정은 허용하지 않는다.
- (설계자 판단) 구글/카카오로 먼저 가입한 이메일로 이메일 회원가입을 시도하면 PocketBase가 중복 에러를 낸다. 이때 "이미 가입된 이메일입니다. 구글/카카오로 로그인하거나 비밀번호 찾기로 비밀번호를 만드세요" 안내를 보여준다.

### 소셜 계정 연결 (이메일이 달라도)
- 이메일로 가입한 사람이 설정 > 내 계정에서 구글·카카오를 연결할 수 있다. 소셜 쪽 이메일이 달라도 연결된다.
- 방법: 로그인된 상태에서 `authWithOAuth2`를 호출하면 PocketBase가 현재 계정에 외부 계정을 연결한다. 빌더가 사용 중인 PocketBase 버전에서 이 동작을 먼저 확인한다.
- 연결 후에는 그 소셜 계정으로 로그인해도 같은 계정으로 들어온다.
- 연결 해제: `_externalAuths` 레코드 삭제. 단, 로그인 수단이 하나만 남으면 해제 버튼을 막는다 (계정 잠김 방지).
- 이미 다른 계정에 연결된 소셜 계정을 연결하려 하면 "이미 다른 계정에 연결돼 있습니다" 안내.

### OAuth 콘솔
- 구글 클라우드 콘솔, 카카오 개발자 콘솔에 앱 등록.
- 리다이렉트 URL: `https://<pocketbase 도메인>/api/oauth2-redirect`

## 5. 클라이언트 (Tauri 위젯)

### 스택
U-Drive(`D:\project\cloude-drive`)와 같은 스택을 쓴다.
- Tauri 2, React 19, Vite, TypeScript
- Tailwind v4, shadcn(base-ui), Pretendard
- React Query, pocketbase JS SDK
- 아이콘: U-Drive와 같은 것 (tabler)
- Tauri 플러그인: opener(OAuth 브라우저 열기), autostart, store(토큰 저장), notification(타이머 종료 알림), single-instance

### 창
- 타이틀바 없는 창(`decorations: false`), 가로 기본 500px, 세로는 화면 작업 영역 높이에 맞춤, 화면 오른쪽 끝에 붙는다.
- 상단 얇은 바: 드래그로 이동 가능, 설정 버튼, 숨기기 버튼.
- 작업 표시줄에 안 보이고 트레이 아이콘으로 표시/숨김.
- 창 위치와 크기는 기억해서 다음 실행 때 복원.
- (설계자 판단) 처음 실행 시 주 모니터 오른쪽 끝에 놓고, 이후엔 자유롭게 드래그. 가장자리 달라붙기는 없음. 높이는 사용자가 창 끝을 끌어 바꿀 수 있다. 저장된 위치가 연결된 모니터 밖이면 기본 위치로 되돌린다.
- 위젯은 화면 공간을 차지하지 않는다. 다른 창 위에 떠 있는 일반 창이다 (AppBar 아님).

### 위젯 레이아웃 (A안 확정)
위에서 아래로 세로로 쌓는다. 꺼진 섹션은 사라지고 나머지가 공간을 나눈다.

1. **뽀모도로 타이머**
   - 큰 남은 시간 표시, 현재 단계(집중/휴식), 몇 번째 집중인지.
   - 시작 · 일시정지 · 리셋 · 건너뛰기.
   - 집중 → 짧은 휴식 반복, N회 집중 뒤 긴 휴식.
   - 단계가 끝나면 윈도우 알림 + 소리. 다음 단계는 자동 시작하지 않고 사용자가 누른다.
   - 상태는 로컬만. 앱을 껐다 켜면 리셋된다.
2. **투두** (남은 공간을 가장 많이 차지)
   - 목록, 체크, 추가(하단 입력), 삭제, 제목 수정(더블클릭).
   - 미완료가 위, 완료는 아래로 내려가고 흐리게.
   - 완료 항목 모두 지우기 버튼.
3. **미니 캘린더**
   - 이번 달 월간 그리드, 일정 있는 날에 점 표시, 오늘 강조, 이전/다음 달.
   - 날짜를 누르면 그날 일정 목록 + 추가 폼이 펼쳐진다 (제목, 선택적 시간, 메모).
   - 일정 수정, 삭제.

### 로그인 화면
- 로그인하지 않았으면 위젯 대신 로그인 화면.
- 이메일 + 비밀번호, 구글로 로그인, 카카오로 로그인, 회원가입, 비밀번호 찾기.
- OAuth: SDK의 `authWithOAuth2`에 `urlCallback`으로 Tauri opener를 넘겨 시스템 브라우저에서 로그인. PocketBase가 실시간 채널로 토큰을 돌려준다.
- 토큰은 Tauri store 플러그인 파일에 저장 (localStorage 금지 규칙). SDK의 `AsyncAuthStore`로 연결.
- 서버 주소는 빌드 시 환경변수로 고정 (사용자가 바꾸지 않는다).

### 설정
U-Drive의 설정 대화상자(`src/features/settings/SettingsDialog.tsx`)와 같은 모양: 왼쪽 탐색 + 오른쪽 Section/Row 목록, Segmented, Checkbox. 위젯이 500px라 설정은 **별도 창**으로 연다 (U-Drive 대화상자 크기 880px 기준).

설정값은 U-Drive `appPrefs.ts`처럼 로컬에 저장(PC마다 다름). 토큰이 아닌 단순 설정이라 localStorage 사용 가능, 두 창 간 동기화는 storage 이벤트로.

**일반**
| 항목 | 컨트롤 | 기본값 |
|---|---|---|
| 테마 | 시스템 / 라이트 / 다크 | 시스템 |
| 화면 크기 | 90% / 100% / 110% / 125% | 100% |
| 위젯 너비 | 400 / 500 / 600px | 500 |
| 항상 위에 표시 | 체크 | 켬 |
| 위젯 투명도 | 70~100% | 100% |
| 컴퓨터 켜면 자동 실행 | 체크 | 끔 |
| 창을 닫아도 트레이에서 실행 | 체크 | 켬 |

**위젯 구성**
| 항목 | 컨트롤 | 기본값 |
|---|---|---|
| 뽀모도로 표시 | 체크 | 켬 |
| 투두 표시 | 체크 | 켬 |
| 캘린더 표시 | 체크 | 켬 |

**뽀모도로**
| 항목 | 컨트롤 | 기본값 |
|---|---|---|
| 집중 시간 | 분 입력 | 25 |
| 짧은 휴식 | 분 입력 | 5 |
| 긴 휴식 | 분 입력 | 15 |
| 긴 휴식까지 집중 횟수 | 숫자 | 4 |
| 알림음 | 체크 | 켬 |

**내 계정**
- 이메일.
- 로그인 방식: 구글, 카카오 각각 연결됨/연결 안 됨 표시와 연결·해제 버튼.
- 비밀번호: 소셜로만 가입해 비밀번호가 없으면 "비밀번호 만들기"(재설정 메일), 있으면 "비밀번호 변경".
- 로그아웃.

## 6. 데이터 흐름
- React Query로 todos, events를 불러오고 mutation 후 invalidate.
- queryKey 팩토리 패턴 (`todoKeys.all`, `eventKeys.month(yyyy-mm)`).
- 창에 포커스가 올 때 다시 불러온다 (React Query 기본 refetchOnWindowFocus).
- 오프라인이면 에러 토스트, 로컬 큐는 만들지 않는다.

## 8. 빌더에게 맡기는 것
- 세부 시각 디자인 (U-Drive 톤을 따르되 위젯에 맞게).
- SMTP 서비스 선택.
- PocketBase 버전, Docker 베이스 이미지.
- 위젯 너비 변경 시 창 위치 재계산 방식.
- 테스트 범위 (뽀모도로 상태 전환 로직은 단위 테스트 필수).
- 코드 서명 방식 (인증서 구매 vs 서명 없이 SmartScreen 안내).

## 9. 설계자가 정한 것 (사용자 확인 필요)
- 뽀모도로 기록 저장 안 함, 상태는 로컬.
- 설정은 PC 로컬 저장 (서버 동기화 안 함).
- 실시간 동기화 안 함.
- 일정은 하루 단위 + 선택적 시간, 반복 없음.
- 서버 주소는 빌드 시 고정.
- 앱 안에서 이메일 회원가입 허용.
- 위치는 자유 드래그 + 기억, 높이 조절 가능, 가장자리 달라붙기 없음.
- 카카오에서 이메일이 안 오면 로그인 차단.
- 중복 이메일 가입 시 소셜 로그인/비밀번호 찾기 안내.

## 10. 배포 (공개, 지인 사용)
- 공개 배포. 본인과 지인이 각자 가입해서 쓴다.
- 설치 파일: GitHub Releases에 Windows 설치 파일 업로드.
- 자동 업데이트: U-Drive와 같은 방식 (tauri updater 플러그인 + GitHub Releases의 latest.json, 서명 키).
- 구글 OAuth 앱은 "프로덕션"으로 게시. 이메일·프로필 기본 범위만 쓰므로 민감 범위 심사는 없지만, 동의 화면 브랜딩 정보(앱 이름, 개인정보처리방침 URL)는 채운다.
- 카카오 앱도 이메일 동의항목 설정 후 운영 상태로 둔다.
- 가입 남용 방지: v1은 이메일 인증 필수 + PocketBase 기본 rate limit으로 충분.
